Phase 3 follow-ups

Verify against the real InfluxDB needs a Pi rebuild
All checks so far used unit tests, a local server answering 401 and an unused port. On the first rebuild: a normal run logs --WROTE n points to Influx; a wrong INFLUX_PASS logs the error and does not crash.
Store the Ookla failure reason
Only count = 1 is stored. Pass stderr to onError (possible since PR #19) and store it as a low-cardinality tag, or log it.
A failed write exits 0
Shows only in the log, and the batch is not retried. Fine under cron; revisit with the Phase 4 scheduler.
Delete the bad Ookla point from 2026-10-20
New outliers are dropped, but the 17-day uploadLatency already in InfluxDB still skews averages.

Phase 4: architecture next

Collapse command boilerplate

Template method in BaseCommand; command files shrink by about half. Drop the dead try/catch in runCommands.

Targets as configuration

PING_TARGETS / CURL_TARGETS in .env; no rebuild across the Pis.

In-process scheduler

Replaces cron; deletes containerScripts/. Must skip a tick while a batch still runs: a batch with unreachable targets took ~51 s of its 60 s slot.

After Phase 4: diff measurement and field names. They must be byte-identical, or the dashboards go blank.
